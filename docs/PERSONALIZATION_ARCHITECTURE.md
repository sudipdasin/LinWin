# Architecture correction: functional Windows-like personalization

Owner correction: wallpaper is a user-selected asset, not a procedural art requirement. Prioritize the Windows-style workflow over replicating wallpaper pixels. Native Settings > Personalization > Background (also desktop right-click Personalize and Command Palette) offers Picture, Solid color, Slideshow and optional Theme default. Pictures use local file chooser and recent history; slideshow uses a selected directory, minute interval, sorted readable files and skips unreadable images. Fill, Fit, Stretch, Tile, Center and Span are implemented. Span uses virtual screen geometry within the current LinWin surface; this does not create additional surfaces on unoccupied monitors. Changes are deliberately confirmed by Apply, persist in QSettings, and do not change host XFCE wallpaper. Personal wallpapers are independent of theme and have no forced logo. The theme default preserves existing art only as a choice. Missing images fall back to the selected solid color. Images are bounded by file size, decoded dimensions and display cache dimensions. No arbitrary remote URLs or code execution. Native validation and physical XFCE testing are still required.

Next: functional Personalization subpages (Colors, Themes, Lock screen, Start, Taskbar, Fonts); prioritize host-supported real actions, not dummy controls. Audit complete Windows-like settings categories and workflows before visual polish. Do not claim exact Windows shell or final design parity until tested. No GitHub Actions or CircleCI.
