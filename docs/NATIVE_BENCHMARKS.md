# Native benchmark candidate
Render.10 uses an eight-entry app-owned cache for original shell icons. Repeated requests no longer need to regenerate four sizes per glyph. The benchmark compares the previous rasterization function with warm cache retrieval for 800 identical requests per process. It measures construction/show time after QApplication initialization, Linux resident memory after settling, peak RSS including the benchmark, actual widget grab timings (not FPS), wallpaper cache bytes/rebuild count and desktop-widget polling. Three isolated processes per Neon and Minimal theme run against the installed DEB. Hard gates check resources and cache invariants rather than unstable timing targets; raw samples and medians are published. Offscreen CPU measurements are not physical XFCE/GPU results. No timing improvement claimed until measurements exist. Render.9 remains live until all gates pass.
