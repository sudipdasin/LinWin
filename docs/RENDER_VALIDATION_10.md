# Render.10 measurable performance candidate

Baseline Render.9: 14/14 CTest suites, 45 updater tests, 19 validated screenshots, actual container DEB install/remove and successful live deployment. Local x86_64 GCC 14.2 -O2 comparison of the exact old/new procfs parser (7 alternating trials, 10,000 iterations each): 91.6939 ms baseline median, 4.56156 ms optimized median, 20.1014x. 20,000 synthetic equivalence cases plus live sample and malformed input/overflow checks passed. This is parser-only, not end-to-end desktop speed. Exact source blobs verified against the local tested files.

Candidate additionally caches eight original glyphs at four sizes, checks 1,000 warmed requests produce zero additional rasterizations, benchmarks native Qt icon generation and cached retrieval, and stops both external wmctrl polling timers when hidden/minimized. The 1.5s and 2.5s timer periods imply about 64 avoided scheduled polls per minute of inactivity, not a measured CPU reduction. The native test uses a harmless fake executable for timer lifecycle validation. Render must independently run all previous gates plus the new parser benchmark (at least 2x), cache and polling checks; performance reports are published only after success. Candidate native tests pending. Main remains unchanged; GitHub Actions/CircleCI not used. A preexisting branch name conflict was avoided by creating a distinct Render.10 icon cache branch.
