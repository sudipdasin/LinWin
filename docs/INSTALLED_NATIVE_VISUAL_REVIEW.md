# Installed native visual review gate

Preview 14 compiled and passed 19/20 native suites, but confirmed exit failed. The native test now clicks the actual QMessageBox standard buttons instead of calling done() with a button enum (which does not necessarily set the clicked button). Both cancel and confirm assertions remain mandatory.

Preview 15 adds a disposable-profile capture mode to the actual installed DEB executable, on Xvfb/X11 at 1920x1080 and 1672x941, independent of existing offscreen CTest screenshots. It records panel child bounds, visible pinned-cell sizes and Start bounds; verifies real pixels are captured and publishes PNGs and a SHA-256 manifest. Compact JPEGs from only the isolated builder are transported through Render logs in numbered packets so an assistant with log access can inspect the image, even when direct artifact network retrieval is unavailable. No screenshot from a customer's machine is collected. This is a measurable visual QA gate, not a claim of visual fidelity or autonomous aesthetic judgment. No paid infrastructure, GitHub Actions or CircleCI. The old verified release remains live until all gates pass.

## Capture lifetime correction
Preview 15 first build: all 20 native suites passed, including the corrected confirmation flow; six benchmark processes passed, but installed visual capture failed with a null-image warning and exit 7. The nested asynchronous lambda had captured a stack-local QImage by reference after its lifetime ended. Capture the image by value (Qt implicitly shared image storage), report the exact acceptance fields, and always print the available layout audit before rejecting the candidate. Retain the unreleased Preview 15 version; no failed gate is bypassed.

## X11 capture resolution correction
Second Preview 15 build: 20/20 native suites passed and both image captures saved, but both were 480x420 (minimum window size), not the requested Xvfb screens. Xvfb has no window manager to honor fullscreen requests. Explicitly set the frameless capture overlay to primary screen geometry and reject any size mismatch before capturing. Keep the exact-resolution manifest gate intact. No claim of visual acceptance; previous verified release remains live.

## Preview 17: geometry-to-real-window acceptance
The actual Preview 16 capture showed three rendered columns despite a nominal four-column calculation. Reserve the native view's scrollbar and layout inset, explicitly configure wrapping, and gate on four real complete tile rectangles in row one. Stop suggesting the LinWin shell itself as a pinned Settings application. Existing saved pins are not modified. A separate disposable Xvfb session starts actual XFWM4 and two xterm windows; the installed LinWin binary must discover both, activate one via the real taskbar button, reflect X11 active-window identity in its visual state, and normally close the other through its real context action. Runtime Debian dependencies now include wmctrl and x11-utils; XFWM and xterm are only builder test dependencies. Retain the two existing bare-X11 resolution captures and every previous native test. Preview 17 is a candidate, not validated or visually approved yet. A separate always-visible dock and work-area reservation across maximized applications remains an important unsolved architecture requirement; this change does not claim to fix it.
